# 聆序 · 酒店服务质检（本地版）

双击本目录的 `启动聆序.cmd`，然后打开 http://127.0.0.1:8765 。关闭网页不会停止后台服务。重启电脑后再次双击启动。

## 使用

在左侧选择“影像巡检”，可导入一张图片或一段视频，选择场景、勾选检查项，再点击“开始本地分析”。也可直接访问 http://127.0.0.1:8765/#vision 。完成后打开巡检记录查看证据、标记误报或记录整改，支持导出带证据图的独立 HTML 报告和 JSON 数据。

视觉模块采用 Qwen2.5-VL-3B-Instruct 的 Q4_K_M 权重和 Q8_0 视觉投影文件，由本机 llama.cpp 在 8767 端口按需启动。已有语音运行环境的电脑首次安装视觉模块，可在项目目录执行：

```powershell
& "$env:LOCALAPPDATA\HotelVoice\venv\Scripts\python.exe" -m pip install -r local/requirements.txt
& "$env:LOCALAPPDATA\HotelVoice\venv\Scripts\python.exe" -m local.setup_vision
```

模型安装完成后可离线处理。每段视频最多取 8 个时间窗口，每个窗口最多 3 帧，相邻取样目标间隔为 0.5 秒。报告中的时间为实际解码时间。原始文件、采样画面和报告位于 `%LOCALAPPDATA%\HotelVoice\inspections`。当前模型用于辅助初筛，单帧的双手递物、未给出禁入条件的人员进入均列为“无法判断”。

### 语音质检

1. 选择或拖入员工录音，可填写员工姓名、场景和归档备注。
2. 默认选择“中文 / 普通话”“按声纹区分说话人”和“2 人”；有口音的普通话也使用此选项。会议等多人场景可修改人数或选择自动判断。点击“上传并分析”。支持 WAV、MP3、M4A、AAC、OGG、FLAC、MP4、WEBM，每段不超过 30 分钟、150 MB。
3. 在录音详情查看报告、转写和实测音量信息。点击引用可跳转到原话所在音频片段。
4. 回听后确认复核；在待办页勾选处理结果。可以导出可在浏览器打开并打印的 HTML 报告。
5. 删除需在详情里再次确认；删除会同时移除原始音频、回听版本、报告和待办。
6. 已有录音可点击“按说话人重新转写”，生成独立副本，保留原报告和待办。转写页可以给说话人 A、B 等分组命名；名称只适用于该条录音，不会登记跨录音声纹身份。

## 本地分析模式

- **语音转写**：SenseVoice Small 的 ONNX int8 版本，CPU 推理，默认中文模式、2 人对话。同一人连续发言的短停顿（不超过 1.5 秒）在识别前合并，保留语句上下文；不跨越另一人的发言或重叠讲话合并。超长发言内部以最多 30 秒窗口处理，转写完成后合并展示，不把内部窗口逐个列出。未对酒店实际胸牌录音做准确率标定。
- **声纹分组**：Pyannote 说话人分段 + 3D-Speaker 中文声纹特征聚类，全程本地。声纹特征仅用于本次处理，不持久保存；只保存分组、时间段和人工名称。识别出的重叠讲话标为“归属待确认”，并从业务报告中排除。
- **规则初筛**：当千问服务尚未就绪时，按关键词提取场景候选、服务表达、风险线索、需求和待办原话。报告明确显示“规则初筛”；不是完整语义理解，不自动判断员工已完成服务。
- **本地语义分析**：千问 Qwen2.5 1.5B Instruct Q4_K_M，使用 llama.cpp Vulkan 运行。模型就绪后新分析自动使用此模式。场景使用规则初判，摘要使用原话摘录，模型负责结构化分析，再用原话规则补全漏项。轻量模型结果仍需人工复核。
- 不调用 OpenAI API，不需要 API 密钥。模型安装时需要联网下载开源文件；处理录音时只访问 `127.0.0.1`。

## 存储与端口

默认目录为 `%LOCALAPPDATA%\HotelVoice`，避开项目所在 OneDrive 目录：

- `recordings/`：原始录音及用于浏览器回听的单声道 WAV。
- `records.sqlite3`：录音元数据、转写、报告、复核状态、待办。
- `models/`：模型文件、下载分块与模型来源记录。
- `venv/`：隔离的 Python 环境。
- `llama/`：本地模型运行程序。
- `app-server.log`、`model-server.log`：运行日志，不记录完整对话请求。

应用监听 `127.0.0.1:8765`，本地模型监听 `127.0.0.1:8766`。仅面向本机单用户，不是可直接对外开放的多用户服务。录音没有应用层静态加密，访问由本机账户权限控制。

## 开发与验证

前端是 React + Vite，后端是 FastAPI + SQLite。`vite.local.config.ts` 是本地构建配置。早先 Sites 模板及 `.openai/hosting.json` 不用于本地启动，不发布此应用。

```powershell
npm run build
npm run check
& "$env:LOCALAPPDATA\HotelVoice\venv\Scripts\python.exe" -m unittest local.test_review local.test_speech -v
```

首次环境安装使用 `local/requirements.txt`。模型下载使用 `local/setup_models.py`，支持保留已完整下载的分块重试，检查模型 SHA-256，结束后自动启动本地服务。

说话人模型安装：`& "$env:LOCALAPPDATA\HotelVoice\venv\Scripts\python.exe" -m local.setup_speakers`。`local/speaker_smoke.py` 使用两种本地合成声音检查自动分组及同一声音再次出现的一致性，不代表真实胸牌录音准确率。

`local/smoke.py` 使用 `qa/餐厅服务-合成测试.wav` 验证上传、回听、转写、场景、报告、复核与任务保存。该文件由 Windows 中文语音合成产生，不能用于代表真实酒店噪声环境的效果。

## 已知边界

- 声纹分组不等于身份识别，可能把同一人拆组或不同人混为一组。填写员工仅用于归档，不能证明每句话都是该员工所说。尚未建立员工声纹登记和跨录音识别功能。
- 新版按连续发言显示说话人和文本，时间戳是发言范围，并非每个字的精确时间；原有结果保持原格式，重新转写后才使用新版。选择 2 人是对算法的约束，不能证明录音确实只有两人或每句归属正确。
- 单声道多人同时讲话尚未做声音分离；重叠检测也可能漏检。需要回听核对说话人分组和内容。
- 不尝试恢复完全没录到的客户声音；低声、噪声和多人重叠可能导致误识别。
- 电平和接近满幅采样比例是信号指标，不代表客户可听清率，也不是准确的信噪比。
- 语义报告逐项验证引用确实出现在转写中，但引用存在不代表结论一定正确。摘要采用原话摘录，避免小模型改写带来的角色与执行状态错误；转写和其他推断仍可能出错，正式使用前必须回听，当前不适合直接作为员工考核结论。
- 未明确说出的任务负责人和日期保留“待确认”；没有证据不当作服务未执行。
- 长录音分批生成报告后合并，不对跨批次矛盾自动裁决；不自动合并客户画像。
- 模型报告达到输出长度限制时，对应批次保留规则初筛，并在报告中注明。自动声纹分组只用于转写与回听，不作为模型判断员工身份的依据。
- 尚未接入 PMS，未提供正式员工评分、跨录音声纹身份识别、客户心理推断或自动对客话术。
