# 栖鉴 · 酒店智能巡检与服务分析（本地版）

双击本目录的 `启动栖鉴.cmd`，然后打开 http://127.0.0.1:8765 。关闭网页不会停止后台服务。重启电脑后再次双击启动。

## 使用

在左侧选择“摄像头巡检”，进入“巡检记录”可查看全部记录或筛选待整改记录。点击“新建巡检”，导入一张图片或一段视频，选择场景、勾选检查项，再点击“开始本地分析”。也可直接访问 http://127.0.0.1:8765/#vision 。完成后打开巡检记录查看证据、标记误报或记录整改，支持导出带证据图的独立 HTML 报告和 JSON 数据。

视觉模块采用 Qwen2.5-VL-3B-Instruct 的 Q4_K_M 权重和 Q8_0 视觉投影文件，由本机 llama.cpp 在 8767 端口按需启动。已有语音运行环境的电脑首次安装视觉模块，可在项目目录执行：

```powershell
& "$env:LOCALAPPDATA\HotelVoice\venv\Scripts\python.exe" -m pip install -r local/requirements.txt
& "$env:LOCALAPPDATA\HotelVoice\venv\Scripts\python.exe" -m local.setup_vision
```

模型安装完成后可离线处理。常规检查每段视频最多取 8 个时间窗口，每个窗口最多 3 帧，相邻取样目标间隔为 0.5 秒。报告中的时间为实际解码时间。原始文件、采样画面和报告位于 `%LOCALAPPDATA%\HotelVoice\inspections`。当前模型用于辅助初筛，单帧的双手递物、未给出禁入条件的人员进入均列为“无法判断”。

### 前台举手仪容检查

在“添加点位”页填写点位名称和 RTSP 视频流地址，或选择“批量添加”每行填写一个点位。保存后可在下方的“已配置点位”中修改、暂停或立即巡检。选择“前台接待”后，可分别填写领带款和扎发款的工服特征，例如领型、剪裁、颜色。启用后在整个画面持续检测举手，点位列表显示监听与断线重连状态。常规巡检间隔继续用于微笑服务和双手递物。升级已有安装时，在上方两条安装命令完成后重启本机服务，激活 MediaPipe 姿态检测和本地 Pose Landmarker Lite 模型。

全身从头到双脚入镜，脸和躯干正对镜头，将左手或右手举过同侧肩部，另一只手自然放下，举手保持半秒。举手后可放手，须在 12 秒内朝同一方向慢慢转一圈，依次展示一侧、背面、另一侧并重新面向镜头。系统为同一人保存带框正面全景、各角度全身及头部、下装和鞋履证据；转完生成一条记录。半圈折返、超时、出画或多人交叉后目标不明时，本次取证作废，可重新举手。两侧手腕、髋、膝和双脚须清楚可见，举手时只有半身入镜、侧身或柜台遮住下半身均不会触发；转身过程中下半身被挡住也会取消此次检测。全画面内的客人也可能举手，可在报告中标记误报。

在“巡检记录”点击“新建巡检”，上传前台视频并勾选“仪容仪表”时，按每秒约 4 帧扫描整段视频；8 个时间窗口的限制适用于其他检查。上身工服只检查是否穿西装外套。外套款式用于选择领带或扎发检查；胸牌、下装、皮鞋逐项检查；皮鞋按露出的鞋头、鞋侧或鞋底边缘判断，只露出一只脚也可检查。按款式检查领带或扎发，短于肩部免扎。转身报告结合背面和侧面检查盘发、发网，结合不同角度分别核实左右脚。前台举手仪容报告逐项显示“未见异常”或“发现异常”。完全缺少可辨认的部位证据时，记为“发现异常”，原因注明“取证缺失”。举手报告可复核和导出。单张图片继续沿用原有检查。

### 语音质检

1. 在「挂牌与胸牌语音 → 录音档案」查看所有录音，按设备类型、设备名称或编号筛选。点「上传录音」导入文件。管理员和经理可点每行的「管理」修改名称、员工及备注，或确认删除本机录音、转写、报告与待办。
2. 默认使用中文转写。声纹模型就绪时默认按 2 人分组，缺少模型时使用普通转写；有口音的普通话也使用此选项。会议等多人场景可修改人数或选择自动判断。点击“上传并分析”。支持 WAV、MP3、M4A、AAC、OGG、FLAC、MP4、WEBM，每段不超过 30 分钟、150 MB。
3. 在录音详情查看报告、转写和实测音量信息。点击引用可跳转到原话所在音频片段。
4. 在报告条目展开「逐项复核」，回听后确认、纠正、排除或撤回。会议纪要分列议题、决定、待确认事项及待办。餐厅客诉确认后可填写处理结果。在销售录音详情中选择或新建客户，再逐项核实需求与标签；「客户档案」可跨录音回听已核实的信息。HTML 和 JSON 导出保留原结论和人工处理历史。
5. 删除需在详情里再次确认；删除会同时移除原始音频、回听版本、报告和待办。
6. 已有录音可点击“按说话人重新转写”，生成独立副本，保留原报告和待办。转写页可以给说话人 A、B 等分组命名；名称只适用于该条录音，不会登记跨录音声纹身份。

### 悦航益设备自动同步

进入「挂牌与胸牌语音」可按名称、编号、岗位、类型和在线状态查找设备。点一行查看设备的最后心跳、电量、录音同步状态及最近录音。设备页可见时约每 30 秒向厂商更新状态。接口失败时保留上次更新时间，超过 90 秒的结果显示为待确认；设备心跳延迟也会单独标出。

栖鉴复用已保存的悦航益机构凭据。首次连接新的机构时，管理员在「平台连接」填写一次厂商签发的 AppId 和 AppSecret。同步启用后，本机后台每分钟读取平台设备清单，登记该机构下支持的挂牌和胸牌，为在线且启用同步的设备查询最新录音。网页可以关闭，栖鉴后台和电脑需持续运行并联网。设备详情支持编辑名称、岗位、暂停、恢复或更换；已停用的设备保留历史录音，自动发现尊重本地停用设置。

新设备首次在线时查询最近 24 小时，之后按已保存进度补查，并回查接入范围内最近七天的迟到分段。机构、设备及厂商文件名共同用于去重。删除本机录音后保留去重凭据，再次同步会跳过同一文件。迁移前标记为测试的录音纳入统一档案和统计。

凭据保存在本机数据库，由 Windows 当前用户的 DPAPI 加密。需要查看或复制时，使用同一 Windows 账户双击应用目录的「查看悦航益接口密钥.cmd」。同步状态会显示鉴权或下载错误，下次查询自动重试。

## 语音转写与场景分析

- **语音转写**：SenseVoice Small 的 ONNX int8 版本，CPU 推理，默认中文模式、2 人对话。同一人连续发言的短停顿（不超过 1.5 秒）在识别前合并，保留语句上下文；不跨越另一人的发言或重叠讲话合并。超长发言内部以最多 30 秒窗口处理，转写完成后合并展示，不把内部窗口逐个列出。未对酒店实际胸牌录音做准确率标定。
- **声纹分组**：Pyannote 说话人分段 + 3D-Speaker 中文声纹特征聚类，全程本地。声纹特征仅用于本次处理，不持久保存；只保存分组、时间段和人工名称。识别出的重叠讲话标为“归属待确认”，并从业务报告中排除。
- **胸牌与挂牌场景报告**：手动上传或设备同步的新录音由本机完成转写和说话人分组，再通过本机隐私脱敏，将连续发言按时间顺序编号发送至 DeepSeek 官方 API（`deepseek-flash`）。普通口语也参与判断。脱敏使用本机 8766 模型服务，失败时可从已有转写重试；原始录音及完整转写保存在本机。新版服务报告导出仅包含报告和来源摘要。管理员在启动服务的账户设置 `DEEPSEEK_API_KEY` 环境变量后重启栖鉴；系统设置显示密钥配置状态。
- **场景分析**：DeepSeek 先根据实际转写识别场景，上传时选填的场景仅供参考。识别结果立即出现在报告顶部，再按已识别的场景分析；分类限定为会议、销售沟通、餐厅服务；有多项独立业务时显示混合场景并列出组成。业务依据不足时可回听确认，预订入住和房卡交付按销售沟通中的预订履约分析。场景识别测试可直接报出场景名，例如“食堂场景识别测试”。会议生成纪要与行动项；销售记录需求、顾虑、对应回应、竞品及标签；餐厅记录服务环节、明确表达的情绪与客诉跟进。先查看结论与待办，展开场景分析明细可逐项查看录音依据。展开“依据与复核”可定位到原话所在的发言片段。长录音分批提取后合并同一事项。
- **重试与历史**：连接超时、限流、余额或密钥异常时，详情显示原因；在同条录音点击“用已有转写重试分析”。旧报告可在详情的场景旁点击“重新识别并分析”，未复核且没有任何结论的旧版空报告可在原录音补分析，其余历史报告使用副本保留复核和待办。

## 存储与端口

默认目录为 `%LOCALAPPDATA%\HotelVoice`，避开项目所在 OneDrive 目录：

- `recordings/`：原始录音及用于浏览器回听的单声道 WAV。
- `records.sqlite3`：录音元数据、转写、报告、复核状态、待办。
- `models/`：模型文件、下载分块与模型来源记录。
- `venv/`：隔离的 Python 环境。
- `llama/`：本地模型运行程序。
- `app-server.log`、`model-server.log`：运行日志，不记录完整对话请求。

自动回归使用 `HOTEL_VOICE_DATA` 指定临时数据目录，可用 `HOTEL_VOICE_MODELS` 指向已有语音模型目录。应用监听 `127.0.0.1:8765`，录音隐私脱敏和电话模块使用的本地模型监听 `127.0.0.1:8766`。此启动方式用于本机单用户；店内多人通过独立 HTTPS 门店入口登录，详见[门店操作](../docs/operations/store.md)。录音没有应用层静态加密，访问由本机账户权限控制。

## 开发与验证

前端是 React + Vite，后端是 FastAPI + SQLite。`vite.local.config.ts` 是本地构建配置。早先 Sites 模板及 `.openai/hosting.json` 不用于本地启动，不发布此应用。

```powershell
npm run build
npm run check
& "$env:LOCALAPPDATA\HotelVoice\venv\Scripts\python.exe" -m unittest local.test_review local.test_speech -v
```

首次环境安装使用 `local/requirements.txt`。模型下载使用 `local/setup_models.py`，支持保留已完整下载的分块重试，检查模型 SHA-256，结束后自动启动本地服务。

说话人模型安装：`& "$env:LOCALAPPDATA\HotelVoice\venv\Scripts\python.exe" -m local.setup_speakers`。`local/speaker_smoke.py` 使用两种本地合成声音检查自动分组及同一声音再次出现的一致性，不代表真实胸牌录音准确率。

`local/smoke.py` 使用 `qa/餐厅服务-合成测试.wav` 验证上传、回听、转写、场景、报告、复核与任务保存。该文件由 Windows 中文语音合成产生，不能用于代表真实酒店噪声环境的效果。

## 已知边界

- 声纹分组不等于身份识别，可能把同一人拆组或不同人混为一组。填写员工仅用于归档，不能证明每句话都是该员工所说。尚未建立员工声纹登记和跨录音识别功能。
- 新版按连续发言显示说话人和文本，时间戳是发言范围，并非每个字的精确时间；原有结果保持原格式，重新转写后才使用新版。选择 2 人是对算法的约束，不能证明录音确实只有两人或每句归属正确。
- 单声道多人同时讲话尚未做声音分离；重叠检测也可能漏检。需要回听核对说话人分组和内容。
- 不尝试恢复完全没录到的客户声音；低声、噪声和多人重叠可能导致误识别。
- 电平和接近满幅采样比例是信号指标，不代表客户可听清率，也不是准确的信噪比。
- 场景报告按 DeepSeek 返回的编号映射到实际原话，但引用存在不代表结论一定正确。摘要和逐项结论使用可回听的转写原话，角色、语气和执行状态仍需核对，正式使用前必须回听，当前不适合直接作为员工考核结论。
- 未明确说出的任务负责人和日期保留“待确认”；没有证据不当作服务未执行。
- 长录音分批提取后根据引用合并，同一事项的前后矛盾需复核；同一客户的资料由人工关联及逐项复核汇总。
- DeepSeek 报告无效或达到输出长度限制时保留转写，支持重新分析。自动声纹分组只用于转写与回听，不作为模型判断员工身份的依据。
- 尚未接入 PMS，未提供正式员工评分、跨录音声纹身份识别、客户心理推断或自动对客话术。

## 在同一地址开发和测试

本机网页和 API 统一由栖鉴服务提供，地址为 http://127.0.0.1:8765 。在应用目录先运行 `npm run build`，双击“启动栖鉴.cmd”。开发网页时可在另一个终端运行 `npm run dev`，保存源码后等待构建完成，再刷新原页面。修改 Python 服务后需重启本机应用进程。页面点击「前台电话 → 通话记录」，数据范围切换为「测试」即可回听测试样本，「电话总览」也有独立的数据范围开关。后台模型服务端口仅供程序内部调用。
